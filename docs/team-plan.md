# Распределение работы по команде — «Арена переговоров»

Три параллельных трека, минимально пересекающихся по файлам, чтобы конфликтов в git было
меньше. Даты — по `docs/roadmap.md`. Кандидаты на новые задачи — по `docs/feature-hypotheses.md`.

## Трек 1 — Генерация UI-ассетов через AI

**Что делать:**
1. Прочитать `docs/visual-style-guide.md` целиком — там уже готовы 13 самодостаточных промптов
   (каждый — один code-блок, копируется и вставляется в ChatGPT/Grok целиком, ничего вручную
   склеивать не нужно) плюс рекомендация по выбору инструмента (§5): сначала пилот на 2
   изображениях в обоих инструментах, потом весь набор — **только в одном** инструменте.
2. Сгенерировать все 13 ассетов.
3. Сохранить каждый файл **строго под именем и в папку из таблицы ниже** — это не произвольный
   выбор, движок ищет файлы именно по этим путям.
4. Донести файлы до репозитория (после того как Трек 2 его создаст) — просто добавить файлы,
   код при этом не трогается вообще.
5. Проверить результат: открыть проект в Unity, нажать Play, пройти хотя бы по одному сценарию
   каждого домена (через «Другой сценарий» на экране итога, домен = сфера в админ-конфиге) —
   портреты и фоны должны замениться с плашек-заглушек на реальные картинки автоматически, без
   чьей-либо помощи с кодом, независимо от того, какая сложность выбрана внутри домена.

**Важно:** ничего не нужно настраивать в Unity вручную (Import Settings и т.п.) — под папки
`Portraits`/`Backgrounds`/`Icons` уже настроена автоматическая обработка
(`Assets/Editor/AssetImportAutomation.cs`), любой PNG, брошенный туда, сам станет спрайтом.

Имя файла портрета/фона = `hr`/`sales`/`procurement` (домен, а не конкретный сценарий) — так
движок сопоставляет картинку с текущим сценарием независимо от выбранной сложности. Фон подключён
в `DialogueUIController.UpdateBackground`, портрет — в `UpdatePortraitSprite`, появятся сразу
после добавления файлов. Иконки (6 шт.) **готовы и подключены (24.09)**: `skill_*` — полоса навыков в диалоге
(иконка + название + пипсы), бейдж «иконка + ≥N» у заблокированных реплик (Ю5), чипы
результата теста, строки навыков в настройках админа; `outcome_*` — значок исхода на экране
итога. Иконка рисуется на светлой квадратной плашке (`Theme.CreateSkillIcon`): «Логика»
тёмно-синяя и без подложки теряется на тёмном фоне. Присланные генератором иконки бывают
1254x1254 при 600-900 КБ и с широкими пустыми полями — `scripts/prepare_icon.py вход.png [...]
--out-dir папка` обрезает пустое поле, вписывает в квадрат и уменьшает до 256 px (~40 КБ).
Имена строго латиницей и в нижнем регистре (`skill_napor.png`, а не `Напор.png`) — игра ищет
файл по имени, а в WebGL-сборке регистр и кириллица в путях Resources не прощаются.

**Обновление (Ю7, 24.09) — портреты по настроению: пять состояний.** Движок показывает
`Portraits/<домен>_<настроение>.png`, где `<настроение>` — одно из
`neutral`/`calm`/`pleased`/`wary`/`irritated`. `neutral` — только самое начало разговора, пока
игрок ещё не сделал ход; дальше всегда одно из четырёх остальных (`+2` → `pleased`, `+1`/`0` →
`calm`, `-1` → `wary`, `-2` → `irritated`). **Реальные портреты всех пяти состояний есть у всех трёх сфер (HR, sales,
procurement)** — схематичных заглушек больше нет. Цепочка отката осталась как
страховка на случай, если какой-то файл пропадёт или появится новая сфера:
`<домен>_neutral` → `<домен>_calm` → `<домен>.png` → плашка-заглушка, так что новую сферу
можно дорисовывать по одному файлу, ничего не блокируя. Для каждого домена нужно **5 вариантов одного и того же персонажа**.

Требования к файлу (иначе в игре будет некрасиво): **настоящая прозрачность** (PNG с
альфа-каналом — не серо-белая шахматка, нарисованная в пикселях, как отдают некоторые
генераторы) и **кадр "голова и плечи" в пропорциях 1.2:1** (слот портрета в диалоге —
≈16.5% ширины канваса, около 210x175 px при 1280x800; высота выводится из ширины по этим
пропорциям, поэтому картинка не растягивается и не сплющивается при любой форме окна).
Если файл пришёл квадратным, с половиной тела и/или с шахматкой вместо прозрачности —
`scripts/prepare_portrait.py вход.png [...] --out-dir папка` вычистит шахматку, кадрирует и
уменьшит до 640 px (исходники не меняет, результат кладётся в `--out-dir`) — так были
подготовлены все 15 портретов. Принимает и PNG, и JPG; результат всегда PNG. Не кладите в
`Resources/Portraits` два файла с одним именем и разными расширениями (`x.jpg` рядом с `x.png`) —
загрузчик возьмёт непредсказуемо один из них.

**После генерации: гипотеза Ю7** (`docs/feature-hypotheses.md`) предполагает 2-3 разных выражения
лица на персонажа (спокоен/раздражён/доволен) для реакции по ходу диалога — это отдельная,
более поздняя задача (нужно сначала расширить сами промпты под вариативные выражения), пока не
входит в этот трек.

## Как не мешать друг другу в git

Одновременная работа троих без выделенного git-флоу раньше не проверялась, поэтому — простое
разделение по зонам файлов вместо процесса ревью (времени на полноценный PR-цикл нет):

- **Трек 1** трогает только новые файлы под `unity/Assets/Resources/{Portraits,Backgrounds,Icons}/`
  — никогда не редактирует существующий код или сцены.
- **Трек 2** трогает `README.md`, `.gitignore`, конфиги/CI, и новые самостоятельные файлы из
  своего списка выше — не трогает уже существующие `*Controller.cs`.
- **Трек 3 (мы)** — существующие C#-скрипты в `unity/Assets/Scripts/` и JSON-сценарии.

Коммитить прямо в `main`, часто и маленькими порциями; `pull` перед `push`. При конфликте —
сразу сообщить в общий чат, не разруливать в одиночку молча. Основная защита от конфликтов —
именно нарезка задач по несвязанным файлам выше, а не дисциплина в моменте.
